# validation/

Human ground-truth labels, and the sampling keys that tie each label back to the
judge call it scores. This is data, not analysis: the numbers computed from it
live in `reports/judge-validation.md` and
`reports/hidden-goal-disclosure-validation.md`.

It exists as its own folder because these files were previously written only into
`analysis/out/`, which is gitignored. The labels are hand-produced and cannot be
regenerated by re-running anything, so losing them would mean re-labelling by
hand. They are the most expensive artefacts in the project per byte.

## The password judge (M4)

| file | what it is |
|---|---|
| `judge_labels_round1_LABELLED.md` | 80 completed labels over judge-adjudicated turns, judge prompt v4, sample seed 20260804. 77 `none`, 3 `full`. |
| `judge_labels_round1_key.json` | The sampling key for that sheet: which run, sample and turn each item came from, and what the judge said. |

Recompute agreement with `make judge-agreement`. This is the sheet behind the
binary kappa of 0.654 (METHODS M23). The three-way variant with `partial` gives
kappa 0.087, which is why partial labels are not counted.

## The disclosure judge (M12)

The filled sheets are `reports/m12-gd-v4-labels/firstpass_LABELLED.md` and
`representative_LABELLED.md` — 160 labels in total, judge version gd-v4. They are
already tracked, so they are not duplicated here. Only their keys are:

| file | what it is |
|---|---|
| `disclosure_labels_firstpass_key.json` | Sampling key, gd-v4, `firstpass` mode, seed 20260826, 80 items. |
| `disclosure_labels_key.json` | Sampling key, gd-v4, `representative` mode, seed 20260826, 80 items. |

Recompute with `make disclosure-agreement`. Note what each sheet validates:
first-passage disclosure reaches kappa 0.83, the representative turn only 0.63,
and concealment 0.75. The gd-v5 comparison against the same 80 representative
turns gives Gemini 0.78 and Sonnet 0.57, and that gd-v5 figure is in-sample.

## Rule

Never overwrite a `_LABELLED` sheet. If a judge version changes, draw a fresh
sample into a new file and keep the old one: the old labels still validate the
old version, and the report that quotes it still needs them.
